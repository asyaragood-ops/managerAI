# infinityAI — бэкенд-роутер на C

Принимает сообщения чата от фронтенда и отправляет их **по каскаду моделей**: сначала ИИ №1 (например, бесплатный Gemini 2.5 Flash), а если у него исчерпан лимит (HTTP 429, quota exceeded) или он недоступен — автоматически ИИ №2, №3… Фронтенду возвращается не только текст, но и **кто ответил** (бэйдж «Ответил: Gemini») и история попыток.

## Аккаунты: у каждого свои ключи

Сайт открывается со страницы входа. **Каждый пользователь регистрируется сам** (логин + пароль) и видит только своё: API-ключи, настройки роутера, лимиты и паузы моделей (лимиты провайдера считаются на ключ, а ключи у всех разные), картинки/аудио/видео, статистику. Чаты хранятся в браузере — тоже отдельно для каждого аккаунта.

- Пароль хранится только как PBKDF2-HMAC-SHA256 (600 000 итераций, случайная соль). После 5 неверных паролей подряд вход в этот логин блокируется на 1 минуту, дальше — до 15 минут.
- Сессия — случайный 256-битный токен в cookie `iai_session` (HttpOnly, SameSite=Lax, 30 дней, продлевается при использовании); в базе лежит только его SHA-256. Скрипты страницы токен не видят.
- **Первый зарегистрированный — владелец сервера**: ему достаются ключи и настройки, сохранённые до появления аккаунтов, и только он может пользоваться ключами из `.env` (параметр `env_keys`).
- Все разделы API, кроме `/api/health` и `/api/auth/*`, без входа отвечают `401`.

Параметры в `config.json`:

| Поле | По умолчанию | Что значит |
|---|---|---|
| `allow_registration` | `true` | `false` — новых пользователей не регистрировать (страница входа скроет вкладку «Регистрация») |
| `env_keys` | `"owner"` | чьи запросы могут использовать ключи из `.env`: `owner` — только владельца, `all` — всех, `none` — никого |
| `cookie_secure` | `false` | `true` — cookie только по HTTPS (включите, если сайт открывается через HTTPS) |

## Как работает каскад

```
POST /api/chat ──► модели config.json + catalog.json, упорядоченные стратегией из «Настроек»:
                     1. выключена / нет ключа             → пропуск
                     2. на паузе после 429 или исчерпан
                        локальный лимит (rpm/rpd в SQLite) → «Основной лимит исчерпан. Переключаюсь на резервный ИИ...»
                     3. «try»: запрос к провайдеру
                        ├─ 200            → ответ + метаданные, стоп
                        └─ «catch»: ошибка классифицируется:
                             429 / quota / 402      → лимит: лог + пауза + следующий ИИ
                             401 / 403 / неверный ключ → пауза 10 мин + следующий ИИ
                             5xx, 529, сеть, таймаут → короткая пауза + следующий ИИ
                             400 / пустой ответ      → следующий ИИ без паузы
```

В C нет `try/catch`, поэтому каждый вызов провайдера возвращает `call_result` с полем `kind` (`ok`, `rate_limit`, `quota`, `auth`, `server_error`, `network`…) — это «пойманное исключение» в явном виде. Логика — в `src/router.c`, классификация ошибок — в `src/providers/provider.c`.

**Сколько ждать после 429.** Пауза берётся из ответа провайдера (`Retry-After` или `retryDelay` у Google). Суточный лимит (`PerDay`) — пауза до конца суток UTC; закончились деньги на платном аккаунте (`insufficient_quota`, 402) — 1 час; иначе 60 секунд. Google пишет «exceeded your current quota» даже на минутном лимите, поэтому одно это сообщение не выключает модель на сутки.

## Картинки, озвучка и видео

Роутер сам понимает, что нужен не текст, а файл, и отправляет запрос в каскад **медиа-моделей** — с теми же правилами переключения при лимитах. Файл сохраняется в `data/media`, в чате показывается картинка, плеер или видео с бэйджем «Нарисовал: FLUX…», «Озвучил: Gemini TTS», «Снял видео: Veo».

| Что | Когда | Кто делает (по порядку стратегии) |
|---|---|---|
| Картинка | «нарисуй…», «сгенерируй картинку/логотип/постер…», draw…; любое сообщение в чате «Изображения» | Cloudflare FLUX.1 schnell, Lucid Origin, Phoenix, SDXL (ключ Cloudflare) → **Pollinations FLUX — без ключа** → Gemini Image (платно) |
| Озвучка | «озвучь: текст», «прочитай вслух…», «озвучь предыдущий ответ» | Gemini 3.1 / 2.5 Flash TTS (ключ Google AI Studio, русский язык); Cloudflare Aura и MeloTTS — только английский |
| Видео | «сгенерируй видео…», «сними ролик…», make a video… | Veo 3.1 (ключ Google AI Studio, **только платный тариф**; генерация 1–6 минут) |

- Закреплённая в чате медиа-модель всегда отвечает файлом, а закреплённая текстовая — текстом (если в сообщении нет явной просьбы нарисовать или озвучить).
- В чатах «Аудио» и «Монтаж видео» обычные вопросы получают текстовый ответ: озвучка и видео — только по явной просьбе.
- **Промпт готовит текстовая модель**: русский запрос «нарисуй кота как в прошлый раз, но синего» превращается в английский промпт с учётом переписки (FLUX и Veo лучше понимают английский). Под картинкой можно раскрыть «Промпт» и увидеть, какая модель его написала. Для озвучки текст после двоеточия читается как есть.
- Файлы раздаёт `GET /api/media/<id>.<расширение>`; папку `data/media` можно чистить вручную — в чате на месте удалённого файла появится пометка.

## Модели каталога — в каскад автоматически

Рядом с `config.json` лежит `catalog.json` — 117 бесплатных чат-моделей из каталога сайта (Groq, Cerebras, OpenRouter, Mistral, Cohere, NVIDIA NIM, GitHub Models, Cloudflare, SambaNova, Scaleway…), с теми же `id`, что и карточки на странице «Модели». **Как только в «Настройках» введён ключ провайдера, все его модели сразу попадают в каскад** — без перезапуска и правки конфигов. Без ключа они в каскаде не участвуют и в `/api/models` не показываются. Модели из `config.json` главнее: при совпадении `id` запись каталога пропускается.

Для Cloudflare Workers AI ключ вводится как `ACCOUNT_ID:API_TOKEN` (ID аккаунта нужен в адресе API).

Каталог генерируется из того же источника, что и фронтенд: `cd ../frontend && python3 scripts/gen_catalog.py --backend-json > ../backend/catalog.json`. API-имена моделей у провайдеров иногда меняются — если провайдер ответит 404 «модель не найдена», модель ставится на паузу на 6 часов и каскад идёт дальше.

## Настройки роутера (страница «Настройки» сайта)

Сохраняются на сервере (`data/infinity.db`) и применяются к каждому запросу:

| Настройка | Что делает бэкенд |
|---|---|
| Автопереключение при лимите | выкл — пробуется только первая подходящая модель; при её лимите возвращается ошибка, резервные не вызываются |
| Порог переключения (50–100%) | при локальных лимитах (`rpd`, `tpd`, `rpmo`) модель пропускается заранее, когда израсходовано столько % (`rpm` — всегда 100%) |
| Стратегия «Дешевле» | бесплатные модели по порядку каскада, платные — в конце |
| Стратегия «Свободнее» | бесплатные модели, начиная с самой незагруженной (по доле израсходованного лимита), платные — в конце |
| Стратегия «Качественнее» | по `priority` (1 — сильнейшие), платные модели не откладываются |
| Сохранять контекст | выкл — резервной модели после переключения отдаётся только последнее сообщение |
| Уведомлять о переключении | плашка в чате (выполняет сайт) |
| Шифровать ключи | см. «Безопасность» |
| Вкл/выкл модели на странице «Модели» | выключенные модели каскад обходит, закрепить их в чате тоже нельзя |

Модели, подходящие под специализацию запроса (`skill`), всегда идут раньше остальных; закреплённая в чате модель — первой.

**Локальный учёт лимитов.** Если в конфиге у модели указаны `limits` (`rpm`, `rpd`, `rpmo`, `tpd`), роутер считает запросы и токены в SQLite (`data/infinity.db`) и переключается **заранее**, не дожидаясь 429.

## Сборка на Windows (MSYS2)

1. Установите [MSYS2](https://www.msys2.org/) и откройте терминал **MSYS2 UCRT64**.
2. Поставьте компилятор и библиотеки:
   ```bash
   pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-cmake mingw-w64-ucrt-x86_64-ninja \
                      mingw-w64-ucrt-x86_64-curl mingw-w64-ucrt-x86_64-sqlite3 mingw-w64-ucrt-x86_64-openssl
   ```
3. Соберите:
   ```bash
   cd /c/Users/Administrator/Desktop/infinityAI/backend
   cmake -S . -B build -G Ninja
   cmake --build build
   ```
4. Запуск тестов: `ctest --test-dir build --output-on-failure`

Запускать `infinity-router.exe` удобнее из того же терминала UCRT64 — там есть нужные DLL (libcurl, sqlite). Чтобы запускать из обычного окна, скопируйте DLL рядом с exe: `ldd build/infinity-router.exe | grep ucrt64` покажет список.

## Настройка и запуск

0. **Одной командой:** из корня проекта `./start.sh` (в терминале UCRT64) или двойной клик по `start.bat` — соберёт бэкенд при необходимости, запустит бэкенд и фронтенд, по Ctrl+C остановит оба.
1. Запуск только бэкенда: `./build/infinity-router` (по умолчанию `http://127.0.0.1:8080`).
2. Фронтенд: `cd ../frontend && npm start` — dev-сервер Angular уже проксирует `/api` на порт 8080.
3. Откройте сайт и **зарегистрируйтесь** (первый аккаунт — владелец сервера).
4. **Ключи — на сайте: Настройки → API-ключи.** Ключ хранится на сервере в `data/infinity.db` только для вашего аккаунта; в браузер он не возвращается. Ключи, которые до появления аккаунтов лежали в браузере, при первом входе переезжают на сервер. Где взять:
   - Google AI Studio — https://aistudio.google.com/apikey (бесплатно)
   - Groq — https://console.groq.com/keys (бесплатно)
   - OpenAI, Anthropic — платные pay-as-you-go
5. Порядок каскада — в `config.json` (сверху вниз). Модель без ключа просто пропускается, так что можно начать с одного Gemini.

`.env` — **необязательный** запасной вариант: ключ оттуда используется, только если для провайдера ключ не задан в «Настройках», и по умолчанию только для владельца сервера (`env_keys`). Связь модели с ключом — поле `key_name`: оно должно совпадать с названием провайдера в «Настройках» (`Google AI Studio`, `Groq`, `OpenAI`, `Anthropic`…).

Пример лога, когда у Gemini кончился бесплатный лимит:

```
WARN  [router] [1a15...] Gemini: Основной лимит исчерпан (HTTP 429: You exceeded your current quota...). Переключаюсь на резервный ИИ...
INFO  [router] [1a15...] Gemini на паузе 41 с
INFO  [router] [1a15...] → GPT-4o (openai/gpt-4o)
INFO  [router] [1a15...] ✓ Ответил: GPT-4o за 812 мс (11+9 токенов) — после переключения
```

### Поля модели в config.json

| Поле | Описание |
|---|---|
| `id` | уникальный id; если совпадает с id карточки во фронтенде (`cat-…`), карточка обновит счётчик |
| `label` | имя для бэйджа «Ответил: …» |
| `provider` | `gemini`, `openai` (любой OpenAI-совместимый API), `anthropic`, `cloudflare`, `pollinations`, `mock` |
| `kind` | `chat` (по умолчанию), `image`, `audio`, `video` — что генерирует модель |
| `keyless` | `true` — ключ не нужен (Pollinations) |
| `model` | имя модели у провайдера |
| `base_url` | для OpenAI-совместимых: `https://api.groq.com/openai/v1`, `https://openrouter.ai/api/v1`, `https://api.mistral.ai/v1`… |
| `key_name` | под каким провайдером ключ хранится в «Настройках» сайта; по умолчанию определяется по `provider`/`base_url` |
| `api_key_env` | необязательно: переменная из `.env`, если ключ не задан в «Настройках» |
| `tier` | `free` / `paid` — только для отображения |
| `skills` | специализации (`text`, `code`, `marketing`…); модели с навыком чата идут в каскаде раньше |
| `limits` | локальные лимиты: `rpm`, `rpd`, `rpmo`, `tpd` (0 или нет — без ограничения) |
| `max_tokens`, `max_tokens_field` | длина ответа; для новых моделей OpenAI `max_tokens_field: "max_completion_tokens"` |
| `priority` | 1 — сильнейшие, 2 — средние, 3 — лёгкие; учитывается стратегией «Качественнее» |
| `enabled` | `false` — временно исключить из каскада |

## API

**POST /api/chat**

```json
{ "messages": [{ "role": "user", "content": "Привет" }], "model": "auto", "skill": "marketing" }
```

`model` — `"auto"` (каскад по порядку) или `id` модели, которую закрепили в чате: она пробуется первой, а при лимите каскад продолжается.

Ответ `200`:

```json
{
  "ok": true, "request_id": "1a1524…",
  "text": "…", "badge": "Ответил: GPT-4o",
  "model": { "id": "openai-gpt-4o", "label": "GPT-4o", "provider": "openai", "model": "gpt-4o", "tier": "paid" },
  "switched": true,
  "usage": { "input_tokens": 11, "output_tokens": 9 },
  "attempts": [
    { "model": { "id": "…gemini…", "label": "Gemini", … }, "status": "quota", "limit": true, "http_status": 429, "latency_ms": 180, "message": "HTTP 429: You exceeded your current quota…" },
    { "model": { "id": "openai-gpt-4o", "label": "GPT-4o", … }, "status": "ok", "limit": false, "http_status": 200, "latency_ms": 812, "message": "" }
  ],
  "latency_ms": 1001
}
```

Если не ответил никто — `503` с `"ok": false`, `"error"` и тем же списком `attempts`.

**GET /api/models** — каскад с состоянием: есть ли ключ, счётчики за минуту/сутки/месяц, пауза и её причина.
**POST /api/models/{id}/reset** — снять паузу и обнулить счётчики модели.
**GET /api/health** — проверка, что сервер жив.

**Ответ с файлом.** Если просили картинку, озвучку или видео, в ответе `/api/chat` есть `"kind":"image"|"audio"|"video"`, `"media":{"url":"/api/media/1a15….png","mime":"image/png","bytes":123456}`, `"prompt"` (что ушло модели) и `"prompt_model"` (кто его подготовил); `"badge"` — «Нарисовал: …», «Озвучил: …», «Снял видео: …».

**Аккаунт** (тело — JSON; `tz` — смещение часового пояса в минутах, Москва: `180`):
- `POST /api/auth/register` `{"login":"anna","password":"…","tz":180}` — регистрация и сразу вход (ставит cookie). Логин — 3–48 символов `A–Z a–z 0–9 . _ - @ +`, пароль — от 8 символов.
- `POST /api/auth/login` — вход; `401` — неверный логин/пароль, `429` + `retry_after` — временная блокировка.
- `POST /api/auth/logout` — выход (сессия удаляется на сервере).
- `GET /api/auth/me?tz=180` — кто вошёл (`401`, если никто); отмечает день посещения.

**Статистика** — `GET /api/stats?days=371`:
```json
{ "ok": true, "today": "2026-10-19", "tz": 180,
  "days": [{ "day": "2026-10-19", "visited": true, "requests": 142, "tokens_in": 51380, "tokens_out": 77070, "media": 3, "switches": 4 }],
  "daily_limit": 1000000, "used_today": 128450, "limits_reset_at": 1792454400,
  "models": [{ "id": "…", "label": "Gemini", "provider": "Google AI Studio", "kind": "chat", "rpd": 20, "req_day": 19, "tpd": 0, "tokens_day": 41200, … }],
  "left": { "tokens": null, "requests": 914, "token_models": 0, "request_models": 3 } }
```
День считается в часовом поясе пользователя. В `days` — только дни с активностью; день посещения отмечается при открытии сайта и при каждом запросе. `left` — сколько осталось на сегодня по суточным лимитам провайдеров (`null` — у подключённых моделей такого лимита нет).

**Дневной лимит токенов** (`dailyTokenLimit` в настройках, по умолчанию 1 млн, `0` — без лимита): когда за сегодня израсходовано столько токенов, роутер перестаёт отвечать до полуночи по вашему времени. Это «осталось сегодня» на вкладке «Статистика».

**Настройки** (только своего аккаунта и только со своего сайта):
- `GET /api/settings` → `{"ok":true,"encryption_available":true,"settings":{"autoSwitch":true,"threshold":90,"strategy":"free","keepContext":true,"notifySwitch":true,"encryptKeys":false,"dailyTokenLimit":1000000,"disabled":[]}}`
- `POST /api/settings` — частичное обновление, например `{"strategy":"quality","threshold":80}`. Неверные значения → `400`.

**Ключи** (свои ключи вошедшего пользователя; изменения — только со своего сайта, проверяется заголовок `Origin`):
- `GET /api/keys` — провайдеры каскада и сохранённые: `{"provider":"Groq","set":true,"source":"settings"|"env","hint":"…a1B2","models":["Llama 3.3 70B"]}`. Сам ключ сервер никогда не возвращает.
- `POST /api/keys` `{"provider":"Groq","key":"gsk_…"}` — сохранить; пустой `key` удаляет. После смены ключа пауза моделей этого провайдера снимается.
- `POST /api/keys/bulk` `{"keys":{"Groq":"…","OpenAI":"…"}}` — так при первом входе на сервер переезжают ключи, которые раньше хранились в браузере.

## Безопасность

- Ключи хранятся только на сервере в `data/infinity.db`, отдельно для каждого пользователя; в браузер приходит лишь подсказка «…a1B2».
- **Шифрование ключей** (переключатель в «Настройках»): ключи в базе хранятся как `enc:v1:…` — AES-256-GCM со случайным nonce и проверкой целостности. Мастер-ключ создаётся при первом запуске в `data/master.key`; в Windows он защищён DPAPI (расшифровать его может только ваша учётная запись Windows на этом компьютере), в Linux/macOS — права `0600`. При включении уже сохранённые ключи перешифровываются, при выключении — возвращаются в открытый вид. Шифрование включает каждый пользователь для своих ключей. Не теряйте `master.key`: без него зашифрованные ключи придётся ввести заново. Сервер не отдаёт ключи обратно — только последние 4 символа. `.env` и `data/` в `.gitignore`.
- Менять ключи и отправлять сообщения можно только со своего сайта: запросы с чужим `Origin` отклоняются (иначе любой открытый в браузере сайт мог бы обратиться к `127.0.0.1:8080`). Ключ с пробелами или переводами строк не принимается.
- Картинки, аудио и видео лежат в `data/media/u<id пользователя>/` и отдаются только их владельцу.
- По умолчанию сервер слушает только `127.0.0.1`. Чтобы пускать других людей, выкладывайте его **только за reverse-proxy с HTTPS** (иначе пароли и cookie идут открытым текстом) и включите `cookie_secure`. Если пользователи не должны регистрироваться сами — `allow_registration: false`.
